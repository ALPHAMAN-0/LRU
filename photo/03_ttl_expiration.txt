  ----------------------------------------------------------------------------
  len() vs `in`: a capacity question and a liveness question
  ----------------------------------------------------------------------------
    After the TTL passes, but before anything reads the key:
      len(cache)        -> 1   (it still occupies a capacity slot)
      'ghost' in cache  -> False   (a lookup would not find it)
      cache.keys()      -> []
    purge_expired() sweeps them out on demand:
      cache.purge_expired() -> 1
      len(cache)            -> 0

  This asymmetry is deliberate: keeping len() O(1) is worth more than
  making it liveness-exact, which would cost an O(n) scan per call.
